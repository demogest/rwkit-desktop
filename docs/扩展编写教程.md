# 轮回战场创意工坊 · 扩展编写教程

这份教程讲怎样为轮回战场创意工坊编写作品——**扩展**、**角色**和**开局商店**三种分类：离线包（`.rwpack`）里能放哪些内容、每种内容怎么写、有哪些限制和常见的坑，以及怎样用 **rwkit 离线包工具**（或 rwkit 命令行）完成编辑、检查和打包。

文中所有“必须”“会失败”的规则都来自 rwkit 的校验——它与工坊导入、安装时的检查一致，工具里显示“正常”的包，工坊就能导入和安装。

## 1. 先认识离线包

一个 `.rwpack` 就是一个 JSON 文件，大致结构：

```json
{
  "format": "reincarnation-workshop-project",
  "version": 1,
  "exported_at": 1791895111358,
  "project":  { "id": "…", "name": "回声茶馆", "category": "extension", "version": 3, "…": "…" },
  "manifest": { "…自动生成的校验清单：每个 artifact 的大小与 SHA-256…" },
  "bundle": {
    "schema_version": 1,
    "artifacts": [ { "kind": "worldbook", "format": "json", "name": "茶馆世界书.json", "content": { "…": "…" } } ],
    "resource_overrides": []
  }
}
```

- **project**：项目资料——名称、分类、版本号、简介、标签、封面、依赖。见 [项目资料](#project)。
- **bundle.artifacts**：包的实际内容，1 到 32 个 **artifact**。每个 artifact 是下面五种之一：

| kind | 是什么 | 安装后 |
| --- | --- | --- |
| `worldbook` | [世界书](#worldbook)：设定条目，按关键词或常驻发送给 AI | 加入角色的世界书 |
| `regex` | [正则](#regex)：改写 AI 输出 / 用户输入，或把标记渲染成页面 | 加入角色的正则 |
| `script` | [酒馆助手脚本](#script)：按钮、界面、变量处理等 | 加入酒馆助手脚本 |
| `preset` | [预设](#preset)：酒馆导出的预设 | 出现在预设列表 |
| `data` | [数据](#data)：交给轮回战场本体读取 | 由本体使用 |

- **bundle.resource_overrides**：[原版资源规则](#overrides)——安装后停用或启用原版角色卡里的资源。
- **manifest**：校验清单。**不用手写**：rwkit 打包、rwkit 离线包工具保存时都会自动重新计算。手动改过离线包导致校验对不上时，用“修复”重算即可。

### 离线包与项目文件夹

离线包适合分发；修改时有两种方式：

- **直接编辑离线包**（rwkit 离线包工具）：打开 `.rwpack`，在“编辑内容”里改，修改先进草稿，“保存为新版本”时写出新的 `.rwpack`。适合改几处内容。
- **解包成项目文件夹**：每个 artifact 一个文件夹，世界书一条一个 `.txt`，脚本和页面单独成文件，方便用 VS Code 大量修改，改完再打包：

```text
回声茶馆-v3/
  project.json                  项目资料（manifest 写成“（打包时自动生成）”）
  cover.png                     封面
  01 世界书 · 茶馆世界书/
    artifact.json               这个 artifact 的设置
    entries/                    世界书条目，一条一个 .txt
  02 脚本 · 茶馆按钮/
    artifact.json
    content.js                  脚本正文
  03 正则 · 茶单页面/
    artifact.json
    replaceString.html          替换内容（较长或多行的文字都会拆成单独文件）
```

文件夹开头的编号决定 artifact 在包里的顺序。`artifact.json` 里的 `{"$file": "文件名"}` 表示“这个字段的内容在那个文件里”，打包时自动换回；`{"$entries": "entries"}`、`{"$image": "cover.png"}` 同理。这些引用标记不要手动展开。

### 工坊的硬性限制

| 项目 | 上限 |
| --- | --- |
| 离线包大小 | 6 MB（封面图与内嵌页面都算在内） |
| artifact 数量 | 32 个（至少 1 个） |
| 单个世界书的条目 | 500 条（至少 1 条） |
| 依赖 | 12 个 |
| 原版资源规则 | 300 条 |

**发布到创意工坊**时，服务器另有这些限制（离线导入不受影响；超出时 rwkit 离线包工具的“检查结果”里会提示，发布和上传会被拦下）：

| 项目 | 上限 |
| --- | --- |
| 名称 | 80 个字（不能为空） |
| 简介 | 2000 个字 |
| 更新说明 | 2000 个字 |
| 标签 | 12 个，每个 24 个字（不区分全角半角与大小写，重复的只算一个） |
| artifact 名称 | 100 个字 |
| 上传内容 | 4 MB（不含封面） |
| 单个正则 artifact | 200 条正则 |
| 单个脚本 artifact | 100 个脚本；文件夹里最多 100 个脚本，文件夹不能嵌套 |
| 原版冲突声明 | 每个 artifact 100 条 |
| 原版资源规则 | 300 条，不能重复指向同一个目标 |
| 封面 | 必填；PNG、JPEG 或 WebP，不超过 3 MB |
| 角色作品 | 只能有一种角色用途（世界书角色 / 开局角色 / 开局伙伴） |

## 2. 快速上手：十分钟改出第一个扩展

最快的起点是 rwkit 自带的示例扩展“**回声茶馆**”：它覆盖了常见写法，可以直接导入工坊，也可以改名改内容当作新扩展。

1. 打开 rwkit 离线包工具，点左上角“**打开 / 新建**”→“**生成示例扩展…**”，选一个位置。得到 `示例扩展/` 项目文件夹和 `示例扩展-v1.rwpack`。
   （命令行：`node rwkit.mjs example <文件夹>`）
2. 在“**概览**”页把名称改成你的扩展名，写简介、标签，换封面，点“保存”。
3. 切到“**编辑内容**”：
   - 点“示例·关键词触发·回声茶馆”，把正文换成你的设定，关键词换成你的；
   - 用不到的条目、正则、脚本，在右上角“…”里删除；
   - 需要新内容时，在 artifact 标题上点 `+` 新建条目，或在列表底部“新建 artifact”。
4. 看“**检查结果**”：没有错误（红色）就能打包；提示（黄色）建议也看一下。
5. 点右上角“**打包**”（项目文件夹）或“**保存为新版本**”（离线包），得到新的 `.rwpack`。
6. 在工坊的“**本地**”页导入它。

> 新建一个完全空白的项目：“打开 / 新建”→“新建项目…”。会得到一份带一条常驻条目的世界书，其他内容按需添加。
>
> 示例里每种写法的作用：
>
> | 示例内容 | 演示了什么 |
> | --- | --- |
> | 世界书 990001 常驻总纲 | 常驻条目（每次都发送） |
> | 世界书 990002 关键词触发 | 出现关键词才发送 |
> | 世界书 990003 按深度插入 | 用“按深度插入”放格式要求 |
> | 世界书 990004 EJS 读取变量 | 根据变量决定发送什么 |
> | 世界书 990005 已停用条目 | 停用草稿 |
> | 脚本“示例脚本” | 输入框上方的按钮、读取 MVU 变量、插入消息 |
> | 正则“茶馆茶单页面” | 把 `【回声茶馆】` 渲染成可点击的 HTML 页面 |
> | 正则“茶馆告示美化” | 用 `$1` 捕获组美化一段文字 |
> | 正则“茶单标记不发给AI” | 只改发给 AI 的内容，不影响显示 |

<a id="project"></a>

## 3. 项目资料

在“概览”页编辑（项目文件夹里是 `project.json` 的 `"project"`）。

| 字段 | 说明 |
| --- | --- |
| `id` | 项目的唯一标识，新建时自动生成。**发布后不要改**：工坊靠它识别“同一个项目的不同版本”，别人的依赖也写的是它 |
| `name` | 名称，显示在工坊里（发布到工坊不超过 80 个字） |
| `category` | `extension`（扩展、开局商店）或 `character`（角色），见 [三种分类](#character) |
| `version` | **不小于 1 的整数**。工坊靠它判断新旧：已安装的同一版本不能直接覆盖导入，所以每次发布新内容都要升版本号 |
| `summary` | 简介，显示在工坊作品卡片与“本地”页上（发布到工坊不超过 2000 个字） |
| `tags` | 标签列表（发布到工坊最多 12 个，每个不超过 24 个字） |
| `has_cover` / `cover_url` | 封面。工具里直接选图片或把图片拖到封面区域；离线包里存为 base64，项目文件夹里是 `cover.jpg` / `cover.png` |
| `dependencies` | 依赖的其他工坊项目，见 [依赖](#deps) |

**封面建议**：16:9，几百 KB 以内。封面也计入 6 MB 上限，太大的原图请先压缩。发布到工坊时封面是必填的，只能是 PNG、JPEG 或 WebP，且不超过 3 MB。

<a id="worldbook"></a>

## 4. 世界书

世界书是扩展最主要的内容：一组**条目**，每条是一段设定文字，满足条件时插入到发给 AI 的提示词里。

### 4.1 条目怎样被发送

| 设置 | 效果 |
| --- | --- |
| **常驻**（`constant: true`） | 每次都发送。适合总纲、规则、必须一直生效的设定。注意常驻条目越多，每轮消耗的 token 越多 |
| **关键词**（`key`） | 最近的聊天里出现任意一个关键词时发送。适合地点、人物、物品等“提到了才需要”的设定 |
| **次要关键词**（`keysecondary` + `selectiveLogic`） | 在主关键词命中的基础上再加条件：与任一 / 与全部 / 非任一 / 非全部 |
| **停用**（`disable: true`） | 不发送。写到一半的草稿可以先停用 |
| **触发概率**（`useProbability` + `probability`） | 满足条件后按概率发送 |

> **既不常驻、也没有关键词、也没停用的条目永远不会触发**——rwkit 会对这种条目给出提示。

### 4.2 插入到哪里

| `position` | 位置 |
| --- | --- |
| 0 | 角色定义之前 |
| 1 | 角色定义之后 |
| 2 / 3 | 作者注释之前 / 之后 |
| 4 | **按深度插入**：插在倒数第 `depth` 条消息处，以 `role`（0 系统、1 用户、2 AI）的身份 |
| 5 / 6 | 示例消息之前 / 之后 |
| 7 | 出口（outlet），配合 `outletName` |

`order` 决定同一位置的条目谁先谁后，**越小越靠前**。

经验：设定、背景放在角色定义附近（0 / 1）；**格式要求、输出规范这类要 AI 马上遵守的指令，用“按深度插入”放在离最新消息近的地方**（示例 990003：深度 2、系统身份）。

### 4.3 正文怎么写

- 用一对自定义标签把内容包起来，方便 AI 区分、也方便正则识别：

  ```text
  <回声茶馆>
  位置: 主神空间中枢东侧一条窄巷的尽头
  老板: 阿篱，记性极好，从不打听任务细节
  规矩:
    - 茶馆里禁止动武
    - 可以用故事付账
  </回声茶馆>
  ```

- 正文里可以使用酒馆宏（如 `{{user}}`、`{{char}}`）。
- **EJS**：正文可以写 `<% … %>` 模板，根据变量决定发送什么（需要酒馆装有支持 EJS 的提示词模板扩展）。示例 990004 只在主角位于主神空间时才输出一句话：

  ```text
  <%_
  ;(() => {
    const sd = getMessageVar('stat_data', { defaults: {} }) || {};
    if (String(_.get(sd, '世界.名称', '')) !== '主神空间') return;
  _%>
  主角此刻在主神空间休整，可以顺路去回声茶馆坐坐。
  <%_
  })();
  _%>
  ```

  `<%` 与 `%>` 的数量必须相等，rwkit 会检查。

### 4.4 必须遵守的规则

- 每个条目**必须有名称**（`comment`），否则工坊安装失败。
- **uid 在同一个世界书里不能重复**。在工具里“复制为新条目”会自动分配新 uid；在项目文件夹里复制条目文件新建条目时，一定要改 uid。
- 世界书至少 1 条、最多 500 条条目。

### 4.5 高级设置

| 字段 | 作用 |
| --- | --- |
| `excludeRecursion` | 不被其他条目的内容递归触发 |
| `preventRecursion` | 本条目的内容不去递归触发其他条目 |
| `delayUntilRecursion` | 只在递归阶段才触发 |
| `scanDepth` | 扫描最近多少条消息找关键词（空 = 跟随全局） |
| `caseSensitive` / `matchWholeWords` | 关键词区分大小写 / 全词匹配（空 = 跟随全局） |
| `group` / `groupWeight` / `groupOverride` / `useGroupScoring` | 互斥分组：同组多条命中时只选一条 |
| `sticky` / `cooldown` / `delay` | 触发后持续几轮 / 冷却几轮 / 前几轮不触发 |

条目里的 `extensions` 是这些字段的重复副本（酒馆导出格式如此），rwkit 离线包工具保存时会自动保持一致，不用手动改。

### 4.6 在项目文件夹里写条目

每条一个 `.txt`：两行 `---` 之间是条目设置（JSON），第二行 `---` 之后全部是正文：

```text
---
{
  "uid": 990002,
  "key": ["回声茶馆","阿篱","茶馆"],
  "comment": "示例·关键词触发·回声茶馆",
  "content": "（正文在下方分隔线之后）",
  "constant": false,
  "order": 101,
  "position": 0,
  …
}
---
<回声茶馆>
…正文…
</回声茶馆>
```

文件名只是方便辨认，打包时以设置里的 `uid` 为准；以 `_` 开头的 `.txt` 不会被当作条目。

## 5. 正则

正则在消息显示或发送前，把匹配到的文字替换成别的内容。常见用途：美化 AI 输出的某种标记、把标记渲染成交互页面、在发给 AI 前删掉某些内容。

### 5.1 字段

| 字段 | 说明 |
| --- | --- |
| `scriptName` | 名称 |
| `findRegex` | 查找内容。写成 `/…/标志`（如 `/<告示>([\s\S]*?)<\/告示>/g`），或直接写要找的文字 |
| `replaceString` | 替换为。`$1`、`$2` 引用捕获组，`{{match}}` 代表整段匹配；留空表示删除匹配内容 |
| `placement` | 作用于：1 用户输入、2 AI 输出、3 斜杠命令、5 世界书、6 推理（可多选） |
| `markdownOnly` | 只改**显示**，不改发给 AI 的内容 |
| `promptOnly` | 只改**发给 AI** 的内容，不改显示 |
| `minDepth` / `maxDepth` | 只作用于倒数第几层到第几层（空 = 不限） |
| `trimStrings` | 替换前从匹配内容里去掉的文字 |
| `substituteRegex` | 查找内容里的酒馆宏：0 不替换、1 替换为原文、2 替换为转义后的文字 |
| `runOnEdit` | 编辑消息时也运行 |
| `disabled` | 停用 |

一个正则 artifact 可以放**一条**正则，也可以放**一组**（数组）。每条正则**必须有 `findRegex`**，否则工坊安装失败；查找内容无法编译时 rwkit 会提示。

> rwkit 离线包工具的正则编辑器有**测试区**：粘贴一段聊天文字，实时显示匹配位置和替换结果。

### 5.2 三种常见写法

**文字美化**（只改显示）——示例“茶馆告示美化”：

```text
查找：/<茶馆告示>([\s\S]*?)<\/茶馆告示>/g
替换：<div style='border:1px dashed #b08a5a;border-radius:8px;padding:8px 12px'><b>茶馆告示</b><br>$1</div>
作用于：AI 输出；只改显示
```

配合一条“按深度插入”的世界书条目告诉 AI 什么时候输出 `<茶馆告示>…</茶馆告示>`，就能让 AI 的输出带上固定样式。

**只改发给 AI 的内容**——示例“茶单标记不发给AI”：查找 `【回声茶馆】`、替换为空、只改发给 AI。聊天里照常显示，AI 看不到这个标记。

**渲染成页面**——见下一节。

<a id="regex-page"></a>

### 5.3 HTML 页面

把替换内容整段写成：

````text
```html
<!DOCTYPE html>
<html lang='zh-CN'>
…完整的页面…
</html>
```
````

匹配到的文字就会被酒馆助手渲染成一个页面（iframe），可以写按钮、表单、脚本。示例“茶馆茶单页面”把 `【回声茶馆】` 渲染成可点击的茶单，点单后把文字填进酒馆输入框。

页面要经过酒馆的显示流程，**有些写法会被改写，导致页面错乱或脚本报错**。rwkit 会逐条检查并提示：

| 不要这样写 | 原因 | 改成 |
| --- | --- | --- |
| 直接写 HTML 实体，如 `&amp;`、`&#39;` | 显示时会被解码，可能让脚本语法错误 | 脚本里写成 `'\x26amp;'` 这类转义 |
| 某一行的 `"` 或 `*` 个数是奇数 | 酒馆开启“自动修复 Markdown”时会在行尾补字符 | 属性值全用单引号；`*` 成对出现 |
| 出现 `$1`、`$<` | 会被当作正则捕获组替换 | 换种写法，或拼接字符串 |
| 出现 `{{` | 会被当作酒馆宏替换 | 拆开写，如 `'{' + '{'` |
| 出现 ` ``` ` | 会截断代码块 | 不要在页面里写三个反引号 |
| 出现 `<user>`、`<char>` 等旧式宏 | 会被替换成名字 | 不要用这些标签名 |
| 页面文字能被原版或本包其他正则匹配 | 显示时会插进别的内容 | 避开下面这些写法 |

会被轮回战场原版显示正则匹配的写法（页面源码里不要出现）：`【封面】`、`【开局】`、`<mission>…</mission>`、`<god quest>…`、`<trial quest>…`、`<settlement tasks>…`、`<update>…` / `<updatevariable>…`、`<options>…</options>`、`<CheckResult>` / `<CraftResult>` / `<CombatResult>`、`<dm_think>…`、`<StatusPlaceHolderImpl/>`。

其他要点：

- 页面在酒馆助手的 iframe 里，与酒馆同源，可以通过 `window.parent.document` 操作酒馆界面（示例里把点单文字写进 `#send_textarea`）。
- **iframe 高度**按页面内容量取，不要用 `scrollHeight` 反复撑大，否则会和外层的自动调整互相放大。示例页面里的 `fit()` 函数可以直接参考。
- 生成卡片之类的重复内容时，用 DOM 接口（`createElement`、`textContent`）而不是拼接 HTML 字符串，就不需要处理转义。
- rwkit 离线包工具里点“**预览页面**”可以在沙箱里快速看样式（读取不到酒馆和变量，`$1` 等保持原样）。
- 页面要调用作品脚本或读写 MVU 变量时，用作品页右上角的“**模拟预览**”：在模拟酒馆里导入并打开轮回战场角色卡、安装作品后，点面板里的触发文字按钮插入消息，就能看到页面真实运行的样子，还可以在面板里直接修改变量观察变化。

<a id="script"></a>

## 6. 酒馆助手脚本

脚本由酒馆助手运行，适合做按钮、界面、变量处理等需要代码的功能。

### 6.1 artifact 设置

| 字段 | 说明 |
| --- | --- |
| `scope` | 作用域：`character` 角色脚本（默认）、`preset` 预设脚本、`global` 全局脚本 |
| `format` | 一般是 `json`（下面的脚本对象）；也可以是 `text`，此时 `content` 直接是 JS 文字 |
| `original_conflicts` | [原版冲突声明](#conflicts)（可选） |

`content` 可以是**一个脚本**，也可以是**数组**：数组里放多个脚本，或者文件夹：

```json
{ "type": "folder", "name": "文件夹名", "icon": "fa-solid fa-folder", "color": "", "scripts": [ 脚本, 脚本 ] }
```

### 6.2 脚本对象

| 字段 | 说明 |
| --- | --- |
| `type` | `"script"` |
| `name` | 名称 |
| `id` | 唯一 id（新建时自动生成） |
| `enabled` | 是否启用 |
| `content` | 脚本正文（JavaScript）。**不能为空**，否则工坊安装失败 |
| `info` | 说明 |
| `button` | `{"enabled": true, "buttons": [{"name": "按钮名", "visible": true}]}`：在输入框上方显示按钮 |
| `data` / `export_with` | 脚本数据与导出设置，一般保持默认 |

### 6.3 按钮与常用接口

按钮名要与 `button.buttons` 里的 `name` 一致，用 `eventOn(getButtonEvent('按钮名'), 回调)` 响应点击。示例脚本的骨架：

```js
(function () {
  var BUTTON = '回声茶馆';
  var host = window.parent || window;
  // 脚本运行在 iframe 里：MVU、toastr 等挂在酒馆页面上，先找自己再找外层
  function pick(name) { return window[name] || host[name] || null; }
  if (typeof eventOn !== 'function' || typeof getButtonEvent !== 'function') return;
  eventOn(getButtonEvent(BUTTON), async function () {
    // 读取 MVU 变量；没装 MVU 时不报错
    var world = '未知世界';
    try { world = pick('Mvu').getMvuData({ type: 'message', message_id: 'latest' }).stat_data.世界.名称 || world; } catch (e) {}
    var toastr = pick('toastr');
    if (toastr) toastr.info('你推开了回声茶馆的门。当前所在：' + world);
    if (typeof createChatMessages === 'function') {
      await createChatMessages([{ role: 'assistant', message: '【回声茶馆】' }], { refresh: 'affected' });
    }
  });
})();
```

这里插入的 `【回声茶馆】` 会被正则“茶馆茶单页面”渲染成页面——**脚本 + 正则 + 世界书**配合使用，是扩展最常见的结构。

`eventOn`、`getButtonEvent`、`createChatMessages` 来自酒馆助手，`Mvu.getMvuData` 来自 MVU 变量框架；完整接口以它们各自的文档为准。使用前先判断接口是否存在（如上面的 `typeof eventOn`），在缺少插件的环境里不至于报错。

### 6.4 语法检查

rwkit 会编译脚本检查语法错误（`import` / `export` / 顶层 `await` 相关的报错除外）。rwkit 离线包工具的脚本编辑器会实时检查，出错时点提示跳到对应行。

## 7. 预设

`kind` 为 `preset`、`format` 为 `json`，`content` 是酒馆导出的**预设 JSON 对象**，安装后出现在预设列表里。

- `content` **必须是 JSON 对象**，否则工坊安装失败。
- 做法：在酒馆里调好预设并导出，在 rwkit 离线包工具里“新建 artifact → 预设”，把导出的 JSON 粘贴进编辑器（会实时校验 JSON 格式）。

<a id="data"></a>

## 8. 数据

`kind` 为 `data`：交给轮回战场本体读取的数据，**一般扩展用不到**。数据对象里的 `kind` 决定作品的分类与用途（见 [三种分类](#character)）：

| 数据的 `kind` | 作用 |
| --- | --- |
| `store_catalog` | 开局商店目录：扩展里有它时，工坊把作品归为“开局商店” |
| `world_character` | 世界书角色（角色作品的默认用途） |
| `opening_character` | 开局角色：进入新版开局的角色选择库 |
| `opening_partner` | 开局伙伴：进入新版开局的伙伴选择库 |

- 角色作品里含有 `world_character` 或 `opening_partner` 数据时，该作品的世界书条目会统一放在角色定义之后。
- 开局角色与开局伙伴的字段较多，建议用工坊里的发布表单生成后再下载修改。rwkit 离线包工具里以 JSON 方式编辑。

<a id="store"></a>

### 开局商店目录

```json
{
  "schema_version": 1,
  "kind": "store_catalog",
  "catalog": { "equipments": [], "items": [], "skills": [] }
}
```

在概览页把分类选为“开局商店”会自动添加这份空目录。三类商品都是对象数组，每个商品：

| 字段 | 说明 |
| --- | --- |
| `name` | 名称（必填） |
| `tier` | 品质：`F`、`E` 或 `D` |
| `cost` | 价格：不低于该品质的下限（F 50、E 300、D 700），不超过 1000 |
| `effects` | 效果，最多 2 条 |
| `tags` | 标签，文字数组 |
| `consume` | 消耗（文字，可以为空字符串） |
| `type` | 装备：开局装备分类 0–17；道具：`消耗`、`材料` 或 `特殊`；技能：0 主动、1 被动、2 特殊 |
| `attrs` | 仅装备：原始属性（`力量` `敏捷` `体质` `精神` `魅力` `ATK` `DEF` `MATK` `MDEF` `AP`），值为 F–A，最多 3 项、合计不超过 15 点（F 1 点 … A 6 点） |
| `quantity` / `cd` | 仅道具：数量 1–999；冷却（文字） |

<a id="overrides"></a>

## 9. 原版资源规则

`bundle.resource_overrides`：安装后**停用或启用原版角色卡里的资源**，卸载时恢复。适合“用我的版本代替原版某条设定”这类扩展。在“概览”页最下方编辑。

```json
[
  { "kind": "worldbook", "state": "disabled", "target": { "worldbook": "轮回战场V3.7", "uid": "965161", "name": "阵营-守护者" } },
  { "kind": "regex",     "state": "disabled", "target": { "scope": "character", "name": "某条原版正则" } },
  { "kind": "script",    "state": "disabled", "target": { "scope": "character", "name": "某个原版脚本" } }
]
```

| 字段 | 说明 |
| --- | --- |
| `kind` | `worldbook` / `regex` / `script` |
| `state` | `disabled`（停用）或 `enabled`（启用） |
| `target` | 世界书：至少给 `uid` 或 `name`（可加 `worldbook` 指明世界书）；正则：`scope` 只能是 `character`（可以省略），至少给 `id` 或 `name`；脚本：`scope` 为 `character` / `preset` / `global`，至少给 `id` 或 `name` |

最多 300 条。

<a id="conflicts"></a>

## 10. 原版冲突声明

写在**世界书或脚本 artifact** 上（`original_conflicts`），声明这个 artifact 与原版的哪些条目或脚本冲突，由工坊在安装时处理。在 artifact 设置（导航里 artifact 标题上的齿轮）里编辑。

```json
[{ "action": "disable", "target": { "uid": "123", "name": "原版条目名" } }]
```

- `action`：`disable`（停用原版）或 `replace`（替换原版）。
- 世界书的 `target` 至少给 `uid` 或 `name`；脚本的 `target` 还必须写 `scope`（`character` / `preset` / `global`），并至少给 `id` 或 `name`。

**和原版资源规则的区别**：冲突声明绑定在某个 artifact 上，说明“这个 artifact 和原版的谁冲突”；原版资源规则是整个包级别的，直接列出要停用或启用的原版资源。

<a id="deps"></a>

## 11. 依赖

`project.dependencies`：本包需要先安装的其他工坊项目，最多 12 个。

```json
[{ "project_id": "另一个项目的 id", "min_version": 3 }]
```

- `project_id` 是被依赖项目的 `id`（在它的“概览”页可以复制）。
- `min_version` 是不小于 1 的整数：要求对方至少是这个版本。
- 在“概览”页的“依赖”里添加；已经在工具里打开过的项目会出现在输入提示里。

<a id="character"></a>

## 12. 三种分类：扩展、角色、开局商店

创意工坊按三种分类展示作品，与工坊发布表单一致：

| 分类 | `project.category` | 怎样区分 |
| --- | --- | --- |
| **扩展** | `extension` | 通用扩展：世界书、正则、脚本、预设等 |
| **角色** | `character` | 用途由[数据](#data)决定：带 `opening_character` 是开局角色，带 `opening_partner` 是开局伙伴，否则是世界书角色。一个角色作品只能有一种用途 |
| **开局商店** | `extension` | 带[开局商店目录](#store)（`kind` 为 `store_catalog` 的数据）的扩展 |

三种分类的离线包结构完全相同，用同样的方式编写和检查。在 rwkit 离线包工具的概览页选择分类；选“开局商店”时会添加一份空的开局商店目录。首次发布到工坊后不能再修改分类。

<a id="check"></a>

## 13. 检查、打包与发布

### 13.1 检查分三级

**错误（不改好就无法导入或安装，打包会被拦下）**

- JSON 写坏了（项目文件夹里会指出文件和行号）
- 项目资料无效：缺 `id` / `name`、分类不是 `extension` / `character`、版本号不是不小于 1 的整数、依赖格式不对或超过 12 个
- artifact 数量不在 1 到 32 之间；类型不是五种之一；`format` 不是 `json` / `text`；名称为空；`text` 格式的内容不是文字
- 原版资源规则、原版冲突声明、脚本作用域格式不对
- 世界书没有条目、超过 500 条、条目缺名称；正则缺 `findRegex`；预设不是对象；脚本为空
- 世界书 uid 重复（项目文件夹）；引用的文件找不到或不在项目文件夹内
- 离线包超过 6 MB

**需修复（校验信息与内容不一致）**

手动改过 `.rwpack`，导入时报“大小校验失败 / SHA-256 校验失败”。点“修复”重算即可（原文件另存为 `.bak`）。

**提示（能导入，但内容可能不按预期工作）**

- 世界书条目的键与 uid 不一致；条目既不常驻也没有关键词（永远不会触发）；EJS 标签 `<%` 与 `%>` 不配对
- 脚本语法错误；正则无法编译
- 正则里的 HTML 页面会被酒馆改写（见 [HTML 页面](#regex-page)）

rwkit 离线包工具里，每条提示都能点“去修改”跳到对应条目。

### 13.2 打包与版本号

- **直接编辑离线包**：“保存为新版本”自动把版本号 +1，另存为 `名称-v新版本.rwpack`。
- **项目文件夹**：“打包”时打开“升版本号”，版本号 +1 并写回 `project.json`；输出在项目文件夹旁边。
- 命令行：`node rwkit.mjs pack --bump <项目文件夹>`。

**每次发布新内容都要升版本号**：已安装的同一版本不能直接覆盖导入。

### 13.3 发布前自查

- [ ] 检查结果没有错误，提示都看过
- [ ] 版本号已经升过
- [ ] 简介写清楚：做了什么、需要什么前置（如酒馆助手、MVU）、能否与其他扩展同时启用
- [ ] 有封面（PNG、JPEG 或 WebP，不超过 3 MB），离线包远小于 6 MB
- [ ] 名称、简介、标签等没有超过[工坊的限制](#basics)（检查结果里没有相关提示）
- [ ] 用“改动对比”确认这次改了什么
- [ ] 在工坊“本地”页导入测试一遍

<a id="faq"></a>

## 14. 常见问题与排错

**导入时报“大小校验失败”或“SHA-256 校验失败”**
离线包被手动改过。打开它点“修复”。

**导入时提示已经安装过这个版本**
升版本号后重新打包或保存；或先在工坊里卸载旧版。

**安装时报“第 N 个条目缺少名称 comment”**
给那条世界书条目填上名称。检查结果里点“去修改”可以直接定位。

**条目一直不生效**
看检查结果有没有“永远不会触发”；确认关键词确实会出现在最近的聊天里（或改为常驻）；确认没有停用；用“按深度插入”时确认深度合理。

**页面显示错乱、按钮没反应**
对照 [HTML 页面](#regex-page) 的表格逐项排查，检查结果会指出具体是哪一行。

**页面越来越高**
不要用 `scrollHeight` 设置 iframe 高度，参考示例的 `fit()`。

**正则不起作用**
在正则编辑器的测试区粘贴一段实际的聊天文字看能否匹配；检查“作用于”是否包含 AI 输出，“只改显示 / 只改发给 AI”是否选对。

**项目文件夹里复制了条目文件后打包失败**
多半是 uid 重复。新条目要改 `uid`；在工具里用“复制为新条目”会自动处理。

**离线包超过 6 MB**
压缩封面图；检查内嵌页面里有没有大段 base64 图片。
